# rnsd test1

Первый ручной сценарий для `rnsd`.

Цель теста: убедиться, что демон:

- собирается из исходников;
- стартует с отдельным конфигом;
- поднимает shared instance;
- пишет лог в service mode;
- доступен для локальной проверки через `rnstatus`.

Это базовый smoke/manual test без реального радио-железа и без внешней сети.

## Что именно проверяем

1. Бинарник `rnsd` успешно собирается.
2. `rnsd --help`, `--version`, `--exampleconfig` работают без ошибок.
3. `rnsd` стартует с конфигом из этой папки.
4. В обычном режиме виден успешный старт в stdout.
5. В service mode создаётся файл `logfile`.
6. `rnstatus` может достучаться до shared instance через тот же `-config`.
7. `rnpath` может прочитать path table и запросить путь.
8. После остановки `rnsd` `rnstatus` больше не видит shared instance.

## Ожидаемый результат

- `rnsd` запускается без `exit 1`;
- в логах есть строка вида `Started rnsd version ...`;
- нет строки `connected to another shared local instance`;
- `rnstatus -config <dir> -a` возвращает статус без ошибки;
- `rnpath -config <dir> -t` возвращает path table без ошибки;
- после остановки демона статус через `rnstatus` перестаёт быть доступен.

## Ограничения сценария

- Сценарий не проверяет реальный обмен трафиком между узлами.
- Сценарий не проверяет аппаратные интерфейсы.
- Сценарий использует минимальный конфиг без включённых сетевых интерфейсов.

Следующий сценарий после этого теста: `../test2` проверяет `rnprobe` на transport-enabled узле.
